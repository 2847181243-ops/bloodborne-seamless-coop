# 协作规约详解（按需加载）

> 本文件是 `bbcoop-conventions/SKILL.md` 的详解部分。
> 只在你确实需要判据细节时读它 —— 骨架里已经有"不知道就会做错"的部分。

---

## 1. 证据等级

| 标记 | 含义 | 什么算证据 |
|---|---|---|
| `Confirmed` | 已确认 | 源码 / 反汇编 / 交叉引用 / 运行时日志 / 行为实验 |
| `Probable` | 较强证据，未完全确认 | 一致的间接证据，但缺直接观测 |
| `Hypothesis` | 仅推测 | 有依据的猜想 |
| `Unknown` | 暂无足够证据 | 诚实标注 |

**规则**

1. **禁止把猜测直接当成事实写入核心逻辑。**
2. **未标注等级的结论在 review 中一律按 `Unknown` 处理。**
3. 标 `Unknown` 不丢人 —— 把猜测写成事实才是。
4. 从 `Hypothesis` 升到 `Confirmed` 需要**新的证据**，不是新的措辞。

**常见错误**：把"代码看起来是这样"当成 `Confirmed`。
读过源码只能支撑"源码里是这么写的"；
至于运行时真的这么走，要**运行时证据**才算。

## 2. 版本安全链（任务书 §5.5）

```text
VersionChecker → AddressResolver → HookManager → Game Systems
```

- 版本不匹配 → **禁止**使用旧地址；
- Signature 不匹配 → **禁止**强行 Hook；
- Hook 失败必须明确记录日志，**不允许静默失败**；
- **禁止**因为"可能是这个地址"就直接写入内存。

**为什么这条特别重要**：bbport 直接运行 PS4 可执行文件的转换结果。
游戏更新或 bbport 更新都可能让地址整体位移。
**一个错位的地址不是报错，是静默改错内存** —— 表现为难以复现的崩溃或存档损坏。

任何记录到 `docs/re/` 的地址必须绑定：

```text
游戏版本（1.09 / CUSA03173）
平台（bbport Windows 原生版）
Mod 版本
Signature
```

## 3. 验证链（不允许跳级声明）

```text
Compile Verified → Runtime Verified → Multiplayer Verified → Regression Verified → Feature Verified
```

| 等级 | 含义 |
|---|---|
| `Compile Verified` | 能编译通过 |
| `Runtime Verified` | 在本机真实运行过，观察到预期行为 |
| `Multiplayer Verified` | **真实运行时 + 至少 2P 实测** |
| `Regression Verified` | 改了之后，原本能用的东西仍然能用 |
| `Feature Verified` | 功能完整达成验收标准 |

> **`Build Passed ≠ Feature Complete`**

**报告里只能声明一个等级**，且必须属实。
PR 模板的「当前验证等级」章节由 CI 校验：不能并列声明多个，也不能只有"不适用"。

**常见错误**：写了 `Compile Verified`，然后在同一段里说"等价于 Runtime Verified"。
**"等价"不是证据。** 要么真的跑了，要么就写 `Compile Verified`。

## 4. 版本与兼容

- 版本不匹配时**禁止**复用旧地址（见第 2 节）。
- Mod 与游戏版本、bbport 版本的对应关系必须记录。
- 兼容性优先于新功能（冲突裁决表）。

## 5. 双人签核的实际含义

审计报告要求 `C3-a`（密码学 / 协议 / 完整性）与
`C3-b`（隐私 / 中继 / 抗滥用）**各自独立**出具结论。

**必须如实理解它的强度**：

| | |
|---|---|
| ✅ 机器能验 | 两个角色都出现、各自只有一条结论、结论与标签一致、**证据哈希核对通过** |
| ❌ 机器验不了 | 两个人是否真的独立判断过 |

**不得对外表述为"平台级双人审批"或"审计结论已被机器验证为真"。**
它做了两件事：让漏签可见，让编造证据需要接触真实文件。
它**没有**做的一件事是：证明结论正确。

## 6. 知识的写入位置

判断标准只有一句：**"下一个完全不同的模块也会遇到吗？"**

```text
会  → 平台级 / 类别级 → docs/standards/
不会 → 本模块本版本   → docs/<对应目录>/
```

三条硬规则：

1. **边做边记，禁止批量补记。**
2. **索引必须同步**（`docs/README.md`）。
3. **不确定的必须标注不确定。**

详见 `docs/README.md` 第 5、6 节。
