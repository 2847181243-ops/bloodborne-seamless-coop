## 1. 资产（Assets）

按"一旦受损会直接破坏本项目核心承诺"的程度排序。

| 编号 | 资产 | 为何是资产 |
|---|---|---|
| A-01 | 玩家个人存档（`.bloodco`，与原版 `.sl2` 隔离） | 丢失或损坏 = 玩家进度实质损毁；任务书 §31.3 要求写入原子化、崩溃不损坏 |
| A-02 | 游戏内数据完整性（伤害 / HP / 物品 / 世界进度） | Host Authority 下被篡改会破坏"保留原版风险"的核心承诺（§2.1、§27） |
| A-03 | 会话密钥与会话真实性 | 泄漏即失去 E2EE；任务书要求前向保密与定期轮换（§45.2） |
| A-04 | 玩家身份与会话成员关系 | Sybil / 身份伪造的标的（§45.1 身份攻击） |
| A-05 | 玩家隐私（IP / 平台账号 ID / 硬件指纹 / 位置） | **不可协商红线**（SECURITY.md §2、§45.2 隐私保护） |
| A-06 | 中继节点的中立性 | 中继若可解密 / 篡改 / 重放 / 记录日志，E2EE 名存实亡（§45.4） |
| A-07 | 服务的可用性（信令层 / 中继层） | DDoS 使联机不可用（§45.1 主动攻击、§45.5 抗 Sybil） |

**明确不作为资产收集的对象**：任何玩家隐私数据。项目**无服务器、无官方账号、无中心化身份**
（SECURITY.md §2），因此不存在"服务端账户数据"这一类资产。

## 2. 信任边界（Trust Boundaries）

```text
┌──────────────┐   加密载荷    ┌──────────────┐   加密载荷    ┌──────────────┐
│  Client A    │ ───────────▶ │  中继节点     │ ───────────▶ │  Client B    │
│ （不可信）    │              │ （不可信）    │              │ （不可信）    │
└──────────────┘              └──────────────┘              └──────────────┘
        ▲                                                            ▲
        │                    ┌──────────────┐                        │
        └─────────────────── │  信令 / 发现  │ ───────────────────────┘
                             │ （不可信）    │
                             └──────────────┘
```

| 边界 | 信任假设 | 依据 |
|---|---|---|
| B-01 Client ↔ Client | **互不信任**；每条消息必须自证完整性 | §45.2「每条消息附带 HMAC」「序列号防重放」 |
| B-02 Client ↔ 中继 | 中继**完全不可信**：只能看密文与临时节点标识 | §45.4 中继安全协议 |
| B-03 Client ↔ 信令 / 发现 | 信令不可信；不得据其断言身份 | §45.2「公钥指纹验证（可选，防 MITM）」 |
| B-04 Host ↔ Client | **不对等**：Host 权威，但 Host **本身不可信** | §27、§46.1「Host 作弊无法被完全阻止」 |
| B-05 Mod ↔ 原版存档 | **必须隔离**：Mod 不得改写 `.sl2` | §31.3、§7.5「独立存档机制」 |

> ⚠️ **B-04 是本项目最重要的架构性取舍**：Host Authority 提升了状态一致性，但代价是
> **Host 作弊无法被完全阻止**（§46.1，`:1860`）。这是**设计取舍、不是缺陷**（§46.1 原文），
> 因此威胁模型必须把它记为"接受的残余风险"，而不是"待修复漏洞"。

## 4. 五类攻击与对策

任务书 §45.1（`:1731-1740`）定义五类。以下逐类给出：攻击者能力 → 影响 → 对策 → 对应约束编号
（约束定义见 [constraints.md](constraints.md)）→ 验证方式。

### 4.1 被动攻击（流量窃听 / 流量分析 / 元数据收集）

- **攻击者能力**：可在链路上读取全部字节，但**不修改**。
- **影响**：游戏数据泄漏；元数据（谁与谁联机、何时）泄漏 → 触犯 A-05。
- **对策**：E2EE（X25519 + ChaCha20-Poly1305）；**不使用持久标识**，使元数据无法跨会话关联。
- **约束**：`C-001`（E2EE 强制）、`C-003`（无持久标识）、`C-004`（无隐私数据出网）
- **验证**：AI-C3 代码审计 + AI-C4 MITM/窃听测试；抓包检查出网字段白名单。

### 4.2 主动攻击（MITM / 篡改 / 重放 / 注入 / DoS-DDoS）

- **攻击者能力**：可修改、丢弃、重排、伪造数据包；可洪泛。
- **影响**：状态被伪造（A-02）、消息被重放导致重复发放（S-05）、服务不可用（A-07）。
- **对策**：每条消息 HMAC + **单调递增序列号** + 时间戳窗口；速率限制与包大小上限；
  可选公钥指纹验证防 MITM。
- **约束**：`C-001`、`C-002`、`C-005`（速率限制）、`C-007`（失败不静默）、`C-009`（消息完整性）、
  `C-010`（防重放）
- **验证**：AI-C4 MITM / 重放 / DDoS 测试；AI-C3 代码审计。
- **⚠️ 待裁决-1（MITM 防护等级）**：见 §6。

### 4.3 身份攻击（Sybil / 身份伪造 / 女巫攻击）

- **攻击者能力**：可批量生成节点身份，涌入发现层 / 中继层。
- **影响**：控制大量中继 → 破坏 A-06；放大 DDoS → 破坏 A-07。
- **对策**：新节点默认低信誉；中继数量设上限；大量新节点同时加入触发警报；
  工作量证明与社交验证**均为可选**。
- **约束**：`C-006`（抗 Sybil）
- **验证**：AI-C4 Sybil 测试。
- **⚠️ 待裁决-2 / 待确认（抗 Sybil 量化指标与 PoW）**：见 §6。

### 4.4 中继节点攻击（窃听 / 篡改 / 丢弃数据 / 追踪玩家）

- **攻击者能力**：中继运营者拥有对转发路径的完全控制。
- **影响**：若可解密则 A-03 失守；若可篡改则 A-02 失守；若记录日志则 A-05 失守。
- **对策**：中继**只能**看密文与临时节点标识；**必须**不存储、不记日志、可随时退出。
- **约束**：`C-002`（中继零信任）、`C-008`（中继不记录日志）、`C-011`（中继仅转发）
- **验证**：AI-C4 中继攻击测试（窃听 / 篡改 / 丢弃 / 重放）+ 检查中继侧无日志产出。
- **注**：任务书 §35.15（`:1098`）含「中继无法重放数据」，但 §40 安全 checklist
  （`:1309-1319`）**不含**该项 → 见 §6 待裁决-3。

### 4.5 客户端攻击（作弊 / 扫描 / 攻击其他玩家）

- **攻击者能力**：完全控制自己的客户端与内存。
- **影响**：PvP 不公平；**但 PvE 不得因此被检测**（§46.0）。
- **对策**：**仅 PvP / Invasion** 启用行为反作弊（伤害合理性 / 命中距离 / 攻击频率 /
  位置与 HP 突变 / 无敌帧滥用 / 消耗品异常 / 非法状态切换）；Host 判定伤害与死亡；
  本地黑名单自动拦截。
- **约束**：`C-012`（反作弊仅限 PvP）、`C-013`（客户机自我保护）
- **验证**：AI-C4 客户端攻击测试；AI-C3 审计确认 PvE 路径**无**检测逻辑。
- **⚠️ 红线**：**PvE 模式禁止**行为反作弊检测、伤害与命中校验、因疑似作弊自动踢人、
  写反作弊日志、自动黑名单拦截（§46.0、SECURITY.md §5）。同时**禁止**扫描进程 / 读内存
  （§2.4 非目标、SECURITY.md §2）。

## 5. 已被接受的残余风险（不是缺陷，不修）

| 编号 | 风险 | 为何接受 | 依据 |
|---|---|---|---|
| R-01 | **Host 作弊无法被完全阻止** | Host Authority 架构的必然代价；改为完全阻止会破坏状态一致性与性能 | §46.1（`:1860`）原文："在 Host Authority 架构下，Host 作弊无法被完全阻止"，且把"完全阻止 Host 作弊"列入**不做** |
| R-02 | 本地黑名单可被"改名绕过"，且"同名误伤" | 隐私优先的必然代价：黑名单**只记游戏内显示名称**，不记 IP / 平台 ID / 硬件指纹 | SECURITY.md §2「本地黑名单的边界」明确要求向玩家告知此代价 |
| R-03 | 无中心化封禁 | 项目无服务器、无官方账号 | §2.4 非目标、SECURITY.md §6 |
| R-04 | 版本不匹配时功能不可用（拒绝加载 / 拒绝连接） | 宁可不可用，也不使用错地址（避免内存写入错误） | §5.5 |

**AI-C3 审计要求**：R-01…R-04 **不得**被判为 `FAIL`——它们是显式接受的取舍。
但**必须**核查对应的客户端自我保护（`C-013`）是否全部实现（§46.1 `:1864-1875`）。

## 6. 待裁决与待确认项（**不得由 AI-00/AI-C2 擅自裁决**）

以下项在任务书内部或既有契约中**尚未闭合**。本文件**只记录、不裁决**，按 §49 指明裁决方。

### 待裁决-1：公钥指纹验证是"可选"还是"否决级必需"？

| 出处 | 原文 | 含义 |
|---|---|---|
| §45.2（`:1754`） | 「公钥指纹验证（可选，防 MITM）」 | **可选** |
| §45.3（`:1781`） | 「Step 5：验证公钥指纹（可选，防 MITM）」 | **可选** |
| §53（`:2199`） | AI-C4 验收：`[ ] MITM 攻击防御验证` | **否决级验收项** |

- **冲突**：若指纹验证可选，则 MITM 防御缺少确定性手段，§53 的验收项可能无法达成；
  若视为必需，则任务书两处"（可选）"被升格。
- **裁决方**：**AI-C3**（安全 vs 功能优先级，§49「功能 vs 安全 → AI-C3，安全优先」）。
- **当前处理**：`C-014` 记为**待裁决**，条件项；在裁决前**不得**作为强制约束交付实现方。

### 待裁决-2：抗 Sybil / 抗 DDoS 缺量化指标

| 出处 | 情况 |
|---|---|
| §53（`:2200-2201`） | AI-C4 验收含「Sybil 攻击防御验证」「DDoS 防御验证」 |
| §36（`:1108-1114`） | 性能与网络指标中**没有**任何 Sybil / DDoS 量化基线 |
| §45.5（`:1809`、`:1811`） | PoW 与社交验证均标「（可选）」 |

- **冲突**：「必须验收」但**无判据**，且两个关键机制是可选的 → 无法客观判定通过与否。
- **裁决方**：**AI-C2**（性能 vs 安全，§49）会同 **AI-C4**（提供测试方法）。
- **当前处理**：`C-006`/`C-005` 保留**可验证部分**（中继数量上限、速率限制与包大小上限、
  新节点默认低信誉、大量新节点触发警报），**量化阈值列为待确认**。

### 待裁决-3：「中继无法重放数据」是否为必需项？

| 出处 | 情况 |
|---|---|
| §35.15（`:1098`） | 测试矩阵**含**「中继无法重放数据」 |
| §40 安全 checklist（`:1309-1319`） | **不含**该项（其余 11 项基本一致） |

- **裁决方**：**AI-C3**（安全）→ 建议按"必需"处理（重放已由序列号 + 时间戳覆盖，
  中继重放会因校验失败被拒），但**须裁决后固化为验收项**。
- **当前处理**：`C-010` 覆盖防重放，`C-002` 已含"中继无法重放"；在文件中标注该不一致。

### 待确认-1：既有契约遗留的 4 项

来自 `docs/interfaces/c2_to_b_security_constraints.md` 第 5 节（`:114-117`）：

- [ ] 抗 Sybil 是否启用工作量证明（PoW），以及成本参数
- [ ] 中继节点数量上限与筛选门槛
- [ ] 时间戳防重放窗口与 500ms 延迟阈值的兼容性
- [ ] 信誉数据的加密签名方案

**同理**：§37 待确认项汇总（`:1153`）把**安全审计流程本身**列为待确认。

### 待确认-2：威胁建模范围内的已知空白

- **设计审计（实现前）与持续审计目前无任何门禁**：§45.6 的双签核机制仅覆盖代码审计路径。
- **中继侧取证受限**：「中继不记录日志」既是约束也是测试项（§35.15 `:1315`、§45.4 `:1801`），
  因此中继行为只能通过**审计方自建受控中继**观察，任务书未提供该能力。
