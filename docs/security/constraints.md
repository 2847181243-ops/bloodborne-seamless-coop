## 0. 使用规则

### 0.1 每条约束的必填五要素

```markdown
### C-XXX <标题>
- 要求：<可验证的强制条款>
- 理由：<对应的威胁编号，见 threat_model.md>
- 适用范围：<Agent / 模块>
- 验证方式：<AI-C3 审计项 / AI-C4 渗透项>
- 违反后果：FAIL
```

**禁止**写成"应当尽量""建议考虑"这类不可验证的表述（`docs/security/README.md:41`）。

### 0.2 编号规则

```text
C-0xx —— 通用（适用于所有网络组件）
C-1xx —— 传输层（AI-B1）
C-2xx —— 发现层（AI-B2）
C-3xx —— 信誉层（AI-B3）
C-4xx —— 中继层（AI-B4）
```

本阶段只定义 `C-0xx`（通用）。`C-1xx…C-4xx` 由各层在实现前按同一格式补全，
并须经 AI-C3 设计审计通过。

### 0.3 条件条款的标注

任务书中标注「（可选）」的机制**不得**被本文件升格为强制。
此类条款以 **`【条件条款】`** 前缀标注，并在正文写明待裁决出处。
未裁决前**不约束**实现方，但**须预留接口位**。

## 1. 通用约束（C-0xx）

### C-001 端到端加密强制

- **要求**：所有游戏数据必须经 E2EE 通道传输；**任何明文路径视为缺陷**。
- **理由**：被动攻击（窃听 / 流量分析）、主动攻击（MITM）→ 资产 A-02、A-03、A-05。
- **适用范围**：AI-B1（传输层）、AI-B4（中继）、AI-A2（会话与复制）。
- **验证方式**：AI-C3 代码审计（枚举全部出网路径，确认无明文游戏字段）+ AI-C4 MITM 测试。
- **违反后果**：FAIL
- **依据**：§45.2 `bloodbrone.markdown:1746-1750`；`c2_to_b_security_constraints.md` C-001。

### C-002 中继零信任

- **要求**：中继节点**仅转发加密数据**，**不得**解密、篡改、重放、存储或记录日志。
- **理由**：中继节点攻击（窃听 / 篡改 / 丢弃 / 追踪）→ 资产 A-03、A-06、A-05。
- **适用范围**：AI-B4。
- **验证方式**：AI-C3 代码审计（确认中继进程不持有会话密钥、无业务日志调用、无持久化写入）
  + AI-C4 中继攻击测试（窃听 / 篡改 / 丢弃 / 重放）。
- **违反后果**：FAIL
- **依据**：§45.4 `bloodbrone.markdown:1786-1802`；`c2_to_b_security_constraints.md` C-002。

### C-003 无持久标识

- **要求**：**不得**生成或使用任何持久化节点 ID、设备指纹、硬件标识，
  亦不得生成 Mod 自发的持久 ID。
- **理由**：被动攻击（元数据收集 / 跨会话关联）→ 资产 A-05。
- **适用范围**：AI-B1 / B2 / B3 / B4。
- **验证方式**：AI-C3 隐私审计（落盘内容与出网内容双重检查：搜索持久 ID 生成点与落盘点）。
- **违反后果**：FAIL
- **依据**：§45.2 `bloodbrone.markdown:1765`；SECURITY.md §2；`C-003`。

### C-004 无隐私数据出网

- **要求**：出网报文中**不得**包含 IP、平台账号 ID、硬件信息、地理位置、
  设备信息、系统信息或任何可追踪标识。
- **理由**：被动攻击（元数据收集）、中继节点攻击（追踪玩家）→ 资产 A-05。
- **适用范围**：**全部网络组件**（AI-B1/B2/B3/B4、AI-A2）。
- **验证方式**：AI-C3 抓包审计 + 代码审计（出网字段白名单比对）；AI-C4 中继窃听测试。
- **违反后果**：FAIL
- **依据**：§45.2 `bloodbrone.markdown:1764`；SECURITY.md §2；`C-004`。

### C-005 速率限制与包大小上限

- **要求**：**信令层与中继层必须有速率限制与包大小上限**；新消息类型亦须被覆盖。
- **理由**：主动攻击（DoS / DDoS）→ 资产 A-07。
- **适用范围**：AI-B1 / B2 / B4。
- **验证方式**：AI-C3 代码审计（确认每条接收路径都有上限）+ AI-C4 DDoS 测试（信令层 / 中继层洪泛）。
- **违反后果**：FAIL
- **依据**：§45.2 `bloodbrone.markdown:1768`；`c2_to_b_security_constraints.md` C-005。
- **待确认**：**具体阈值未在任务书给出**（见 §3 待确认-2）→ 阈值属实现方需先提 Issue 确认的参数。

### C-006 抗 Sybil

- **要求**：新节点默认**低信誉**；**中继数量设上限**；**大量新节点同时加入触发警报**。
- **理由**：身份攻击（Sybil / 女巫攻击）→ 资产 A-04、A-06、A-07。
- **适用范围**：AI-B3（信誉层）、AI-B4（中继上限）。
- **验证方式**：AI-C3 代码审计（三项机制均存在）+ AI-C4 Sybil 测试。
- **违反后果**：FAIL
- **依据**：§45.5 `bloodbrone.markdown:1806-1814`；`c2_to_b_security_constraints.md` C-006。
- **待确认**：中继数量上限与筛选门槛未给出（`c2_to_b_security_constraints.md:115`）；
  验收基线缺失（见 §3 待裁决-2）。

### C-007 失败不静默

- **要求**：任何校验失败（HMAC / 序列号 / 版本 / 指纹）**必须记录 `[SECURITY]` 日志并拒绝该消息**。
- **理由**：主动攻击（篡改 / 重放 / 注入）→ 资产 A-02、A-03。
- **适用范围**：**全部组件**。
- **验证方式**：AI-C3 代码审计（逐条失败路径确认有 `[SECURITY]` 记录且返回拒绝，**无静默通过**）。
- **违反后果**：FAIL
- **依据**：`c2_to_b_security_constraints.md` C-007；§34 `bloodbrone.markdown:1050`（`[SECURITY]` 前缀）；
  §5.5 `:220`「Hook 失败必须明确记录日志」「不允许静默失败」。

### C-008 版本强校验

- **要求**：**Mod 版本不一致 → 拒绝连接**；**游戏版本不匹配 → 拒绝加载**；
  **Signature 不匹配 → 禁止强行 Hook**；**禁止因"可能是这个地址"而直接写入内存**。
- **理由**：版本与 Hook 边界攻击面（S-06）→ 资产 A-02（错地址写入 = 内存损坏风险）。
- **适用范围**：AI-A0（平台适配）、AI-A2、**全部网络组件**。
- **验证方式**：AI-C3 代码审计 + §35.13 测试矩阵（版本不匹配场景）。
- **违反后果**：FAIL
- **依据**：§5.5 `bloodbrone.markdown:209-224`（含 `:219`「Mod 版本必须强校验，版本不一致拒绝连接」）；
  `c2_to_b_security_constraints.md` C-008。

### C-009 消息完整性（HMAC + 单调序列号）

- **要求**：**每条消息**必须附带 HMAC，且携带**单调递增序列号**并在接收侧校验。
- **理由**：主动攻击（篡改、注入）→ 资产 A-02。
- **适用范围**：AI-B1（传输层）、AI-C1（密码学实现）。
- **验证方式**：AI-C3 代码审计（确认无"可跳过校验"的路径）+ AI-C4 篡改测试。
- **违反后果**：FAIL
- **依据**：§45.2 `bloodbrone.markdown:1755-1757`；`docs/security/README.md:32-38` 示例。

### C-010 防重放（序列号 + 时间戳窗口）

- **要求**：序列号**单调递增**且校验；时间戳落在**接收窗口**内；窗口外或序列号回退一律**拒绝**。
- **理由**：主动攻击（重放）、中继节点攻击（重放）→ 资产 A-02、A-06。
- **适用范围**：全部网络组件；中继**不得**代为容忍或重写。
- **验证方式**：AI-C3 代码审计 + AI-C4 重放测试（含中继侧重放）。
- **违反后果**：FAIL
- **依据**：§45.2 `:1757-1758`、`c2_to_b_security_constraints.md` C-010；
  §35.15 `:1098` 含「中继无法重放数据」。
- **待确认**：窗口宽度与 500ms 延迟阈值的兼容性（`c2_to_b_security_constraints.md:116`）。
- **⚠️ 不一致已记录**：「中继无法重放数据」在 §35.15（`:1098`）有、在 §40 安全 checklist
  （`:1309-1319`）**没有** → 见 §3 待裁决-3，**不得**由 AI-C2 单方裁决。

### C-011 中继仅转发（可见性最小化）

- **要求**：中继**只能**看到：加密后的数据包、**临时**源标识、**临时**目标标识；
  **不得**看到游戏数据内容、玩家真实 IP、玩家身份、任何元数据；**必须**可随时退出。
- **理由**：中继节点攻击（窃听 / 追踪）→ 资产 A-05、A-06。
- **适用范围**：AI-B4。
- **验证方式**：AI-C3 代码审计（中继侧字段逐一比对白名单）+ AI-C4 中继窃听测试。
- **违反后果**：FAIL
- **依据**：§45.4 `bloodbrone.markdown:1790-1801`。

### C-012 反作弊仅限 PvP / Invasion

- **要求**：行为反作弊（伤害合理性 / 命中距离 / 攻击频率 / 位置与 HP 突变 / 无敌帧滥用 /
  消耗品异常 / 非法状态切换、Host 判定伤害与死亡、黑名单自动拦截）
  **仅可在 PvP / Invasion 模式启用**。
  **PvE 模式禁止**：行为反作弊检测、伤害与命中校验、因疑似作弊自动踢人、
  写反作弊日志、自动黑名单拦截。
- **理由**：功能范围约束（§46.0）→ 防止 PvE 体验被反作弊破坏；同时避免越界监控（资产 A-05）。
- **适用范围**：AI-A2、AI-A4、AI-B3。
- **验证方式**：AI-C3 代码审计（**证明 PvE 路径不存在任何检测调用**，而非仅"默认关闭"）
  + AI-C4 客户端攻击测试。
- **违反后果**：FAIL
- **依据**：§46.0 `bloodbrone.markdown:1831-1857`；§35.13 `:1091-1093`；SECURITY.md §5。
- **补充**：始终启用的**联机基础完整性**与 PvP 专属**行为反作弊**是两套逻辑，审计须分别验证
  （见 §2「始终启用 / 仅 PvP」对照表）。

### C-013 客户机自我保护（Host 作弊下保护自己）

- **要求**：在 Host Authority 下，Client 侧必须实现自我保护：
  角色数据**不被 Host 覆盖**；世界状态**不写入个人存档**；非法物品**拒绝写入**；
  唯一物品**防重复**；存档写入**原子化**；异常中断后**恢复个人进度**；
  玩家**可查看当前 Host 配置**、**可随时退出 Session**、**可清除本地缓存的 Host 世界状态**。
- **理由**：客户端攻击 + `R-01`（Host 作弊无法完全阻止）→ 资产 A-01、A-02。
- **适用范围**：AI-A2、AI-A3、AI-A0。
- **验证方式**：AI-C3 代码审计（逐条确认 9 项存在）+ AI-C4 客户端攻击测试
  （Host 作弊场景下客机数据与存档是否完好）。
- **违反后果**：FAIL
- **依据**：§46.1 `bloodbrone.markdown:1864-1875`。

### C-014【条件条款】公钥指纹验证（防 MITM）

- **要求**（**待裁决，未裁决前不约束实现方**）：首次连接交换公钥后**验证公钥指纹**，
  不匹配则拒绝连接；须**不存在降级路径**（不得回退到"无指纹"继续连接）。
- **理由**：主动攻击（MITM / 中间人密钥替换）→ 资产 A-03、A-02。
- **适用范围**：AI-B1 / B2、AI-C1。
- **验证方式**：AI-C4 MITM 测试（含降级尝试）+ AI-C3 代码审计。
- **违反后果**：FAIL（**仅在裁决为必需后生效**）
- **依据与冲突**：§45.2 `:1754` 与 §45.3 `:1781` **两处均标「（可选）」**；
  但 §53 `:2199` 给 AI-C4 的是否决级验收项「MITM 攻击防御验证」。
- **裁决方**：**AI-C3**（§49「功能 vs 安全 → AI-C3，安全优先」）。
- **裁决前要求**：实现方**须预留指纹验证接口位**（避免裁决后返工），但**不强制启用**。

### C-015 会话密钥轮换与私钥不落盘

- **要求**：会话密钥**定期轮换**；每次会话使用**独立密钥**（前向保密）；
  私钥**只存内存**，**不落盘、不进日志**。
- **理由**：主动攻击（密钥泄漏 / 重放跨会话）→ 资产 A-03。
- **适用范围**：AI-C1（实现）、AI-B1 / B4（使用）。
- **验证方式**：AI-C3 密码学审计（确认轮换触发点在每次会话与周期；确认私钥无落盘/日志路径）。
- **违反后果**：FAIL
- **依据**：§45.2 `:1749-1750`、§45.3 `:1783`；`.github/ISSUE_TEMPLATE/security-audit.yml:58`。
- **待确认**：轮换周期未给出具体值（Q-01）。

### C-016 日志中不得出现隐私数据

- **要求**：任何日志（含调试日志）**不得**记录 IP、平台账号 ID、硬件指纹、
  设备信息、地理位置或任何可追踪标识；日志样例必须脱敏。
- **理由**：日志是隐私泄漏的常见旁路（S-07）→ 资产 A-05。
- **适用范围**：**全部模块**。
- **验证方式**：AI-C3 隐私审计（对全部日志调用点做字段检查；搜索隐私字段进入格式串的路径）。
- **违反后果**：FAIL
- **依据**：§34 `bloodbrone.markdown:1051`「不得记录任何隐私数据」；
  `docs/README.md:54`「文档中不得出现任何玩家隐私数据…日志样例必须脱敏」；
  `.github/ISSUE_TEMPLATE/security-audit.yml:60`（校验失败路径须记 `[SECURITY]` 日志，
  但该日志同样**不得**含隐私字段）。

### C-017 本地黑名单字段白名单

- **要求**：黑名单**只记录游戏内显示名称**（字段白名单为 `display_name` / `note` /
  `created_at` / `expires_at`）；默认**精确匹配**（区分大小写）；
  **不启用模糊匹配**；**必须**向玩家明确告知代价（同名误伤、改名绕过）。
- **理由**：`R-02`（接受的取舍）+ 资产 A-05（唯一允许的身份相关记录，边界必须最窄）。
- **适用范围**：AI-B3、AI-A0（持久化）。
- **验证方式**：AI-C3 隐私审计（检查黑名单 schema 与匹配实现；确认无模糊匹配开关被默认开启）。
- **违反后果**：FAIL
- **依据**：SECURITY.md §2；§46.2 `:1879-1918`（含 `:1895`「不启用模糊匹配」）。

### C-018 存档写入原子化与来源白名单

- **要求**：**所有**存档写入必须**原子化**（先写临时文件，再替换原文件）；
  写入过程中崩溃**不得影响原存档**；**定期（如每 60 秒）**写关键状态到临时文件，
  崩溃后恢复到最近一次安全状态；
  **只写入来源合法的物品**（实时写入 + **来源标记**，优先实现基于"合法来源"的**白名单**机制）；
  Session 异常终止时客机端**超时后自动清理临时世界状态**并安全返回个人进度；
  **不修改原版存档格式**（`.bloodco` 与 `.sl2` 完全隔离）。
- **理由**：存档写入路径攻击面（S-04、S-05）→ 资产 A-01、A-02。
- **适用范围**：AI-A0 / A2 / A3。
- **验证方式**：AI-C3 代码审计（确认无直写原文件的路径；确认来源标记与白名单存在）
  + AI-C4 存档崩溃 / 非法物品注入测试。
- **违反后果**：FAIL
- **依据**：§31.1 `:975-981`、§31.2 `:982-998`、§31.3 `:999-1006`；§7.5「独立存档机制」；
  SECURITY.md §7。

### C-019 非法物品四类检测

- **要求**：必须依四类检测非法物品——**进度越界**（维护"世界进度-物品解锁"对照表）、
  **数量异常**（校验最大堆叠与唯一性标志）、**数值异常**（校验武器强化等级与宝石属性合法性）、
  **来源不明**（实时写入时标记来源，不可追溯者拒绝）；
  **以 Host 世界状态为基准**校验客机关键物品是否"超前"，记录日志并暂时禁用或拒绝加入。
- **理由**：物品发放与奖励攻击面（S-05）、客户端攻击 → 资产 A-02、A-01。
- **适用范围**：AI-A1（原版行为确认）、AI-A2、AI-A3。
- **验证方式**：AI-C3 代码审计（四类检测均存在且不可绕过）+ AI-C4 注入测试。
- **违反后果**：FAIL
- **依据**：§31.2 `:982-998`（表格四类 + 三条核心建议）。
