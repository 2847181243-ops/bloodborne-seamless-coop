## 1. 中继的定位：**零信任中间件**

中继是唯一被任务书明确要求"零信任"的组件。它不是服务端，**不承担任何权威职责**：

- **不**持有会话密钥 → 无法解密（`C-002`）
- **不**存储任何数据 → 无法事后关联（`C-002`、`C-011`）
- **不**记录任何日志 → 无法追踪玩家（`C-008` 反向：日志 = 追踪能力）
- **可**随时退出 → 不构成单点依赖

> **架构推论**：E2EE 的安全性**不依赖**中继的诚实性。若中继可诚实转发即工作，
> 若中继恶意则最坏情况是**拒绝服务**（丢包），而**不是**机密性或完整性失效。

## 2. 四组要求（§45.4 `bloodborne.markdown:1887-1903`）

### 2.1 能看到（可见性白名单）

| 可见项 | 约束 |
|---|---|
| 加密后的数据包 | 允许——密文本身不泄漏游戏数据 |
| 源节点标识（**临时，非持久**） | 允许，但**必须**临时且不可跨会话关联（`C-003`） |
| 目标节点标识（**临时，非持久**） | 同上 |

**白名单性质**：以上**是穷举**。任何不在此列的字段都**不得**出现在中继可见范围内。
审计时应以"白名单外一律视为缺陷"的方式核查，而非"黑名单未命中即通过"。

### 2.2 不能看到

- 游戏数据内容
- 玩家真实 IP
- 玩家身份
- **任何元数据**

**可验证性**：审计方须枚举中继进程可见的全部字段（数据包结构 + 临时标识），
逐项比对白名单（`C-011`）。

### 2.3 不能做

| 禁止行为 | 为何在密码学上成立 |
|---|---|
| 解密数据 | 无会话密钥（`C-002`） |
| 篡改数据 | **HMAC 会失败**（§45.4 原文，`:1797`；`C-009`） |
| 重放数据 | **序列号会失败**（§45.4 原文，`:1798`；`C-010`） |
| 追踪玩家 | 无持久标识 + 无日志（`C-003`、`C-008`） |

> ⚠️ **待裁决-3**：「中继无法重放数据」出现在 §35.15（`:1098`），
> 但**不在** §40 安全 checklist（`:1309-1319`）。
> 本文件按"必需"编写（因为重放防护已由 `C-010` 覆盖），但该不一致**须由 AI-C3 裁决后固化**。
> 见 [threat_model.md §6 待裁决-3](threat_model.md)。

### 2.4 必须做

| 必须项 | 说明 |
|---|---|
| 仅转发加密数据 | 不做任何内容解析、不做深度包检测 |
| **不存储任何数据** | 含磁盘、内存中的长期缓存、任何形式的持久化 |
| **不记录任何日志** | 见 §3 的重要澄清 |
| **可随时退出** | 中继退出不得导致数据损坏或玩家进度丢失 |

## 3. 关于"不记录日志"的三点澄清（审计易错处）

任务书在 §45.4（`:1801`）、§46 与 SECURITY.md 中反复要求"中继不记录日志"。
以下三点必须写清，否则审计会得出矛盾结论：

1. **`[RELAY]` 日志前缀属于客户端**。§34（`:1050`）定义的日志前缀集合供 **Mod 客户端**使用；
   客户端记录"我与某中继的交互"是允许的，**但中继节点本地不得落盘任何业务日志**。
   **不得**把客户端的 `[RELAY]` 日志理解为"中继可以记日志"。
2. **平台自身日志不受本约束支配**，但**不得**被用作绕过手段：
   **禁止**通过"把业务数据写进系统日志/事件日志/stdout 重定向"来规避本条款。
   审计须覆盖 stdout/stderr 重定向与系统日志调用。
3. **"不记录"是为了消除追踪能力**，因此**任何**能在事后重建"谁在何时与谁联机"的信息
   都属于违反——包括内存中的长期映射表。

> **取证限制（已记入遗留风险）**：因为"不记录日志"本身是约束，
> **中继侧的证据只能来自审计方自建受控中继**（观察内存与转发行为）。
> 任务书**未提供**该能力 → AI-C4 需自建，且该需求应回写到 `C-4xx` 约束。

## 4. AI-B4 实现检查清单（可直接逐条勾选）

### 4.1 可见性

- [ ] 数据包在转发前**未做任何解密尝试**，且不持有任何会话密钥
- [ ] 源/目标标识**每次会话重新生成**，不写入任何持久存储
- [ ] 不存在把标识与时间/频率关联并可长期保留的结构

### 4.2 存储与日志

- [ ] 无业务日志调用（含 `printf`/`fprintf`/`std::cout`/平台 logger 等所有形态）
- [ ] 无磁盘写入路径（配置读取除外）
- [ ] 无 stdout/stderr 重定向到文件的路径
- [ ] 内存中无长期映射表（会话结束后即释放）

### 4.3 转发正确性

- [ ] 转发**不修改**载荷任何字节（含填充、重排、重写序列号）
- [ ] 校验失败（若中继参与任何校验）**不得**代为容忍或重写
- [ ] 丢包时不伪造响应

### 4.4 可用性与退出

- [ ] 中继可随时退出，退出**不影响**玩家存档与进度（`C-018`）
- [ ] 速率限制与**包大小上限**已实现（`C-005`）——中继层是 DDoS 的主要承受面

### 4.5 身份与版本

- [ ] 协议版本校验存在，版本不一致**拒绝**（`C-008`）
- [ ] 中继自身**不生成**任何持久标识（`C-003`）

## 5. 对应约束与验证方式

| 要求 | 约束 | AI-C3 审计项 | AI-C4 渗透项 |
|---|---|---|---|
| 仅转发加密数据、不可解密 | `C-002` | 代码审计：确认无密钥持有 | 中继窃听测试 |
| 不可篡改 | `C-009` | 审计 HMAC 覆盖全部消息 | 中继篡改测试（预期 HMAC 失败） |
| 不可重放 | `C-010` | 审计序列号 + 时间戳校验 | 中继重放测试（预期被拒） |
| 不存储 / 不记日志 | `C-002`、`C-008` | 静态扫描 + 运行期观测 | 自建受控中继观察 |
| 无隐私出网 | `C-004` | 出网字段白名单比对 | 抓包审计 |
| 速率限制与包大小上限 | `C-005` | 代码审计每条接收路径 | 信令层 / 中继层洪泛测试 |
| 版本强校验 | `C-008` | 代码审计 | 版本不匹配连接尝试 |
