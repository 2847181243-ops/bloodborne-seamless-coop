## 1. 架构总览

任务书 §45.2（`:1742-1771`）给出 `SecurityArchitecture` 的六个部分。本文件逐部分展开为
**可实现、可验证**的架构决定，并标注对应约束编号。

```text
SecurityArchitecture
├── 端到端加密（E2EE）
│   ├── 密钥交换：X25519（ECDH）
│   ├── 对称加密：ChaCha20-Poly1305
│   ├── 前向保密：每次会话独立密钥
│   └── 密钥轮换：定期更换会话密钥
├── 身份验证：无中心化身份 / 基于密钥对 / 公钥指纹验证（可选，防 MITM）
├── 数据完整性：每条消息附带 HMAC + 序列号防重放 + 时间戳防重放
├── 中继安全：仅转发加密数据 / 无法解密 / 无法篡改 / 无法重放 / 不记录日志
├── 隐私保护：不收集任何隐私数据 / 不使用持久标识
└── 抗攻击：抗 Sybil（信誉 + 可选 PoW）/ 抗 DDoS（速率限制 + 中继隐藏）
             / 抗 MITM（公钥指纹）/ 抗重放（序列号 + 时间戳）
```

## 2. 端到端加密（E2EE）

### 2.1 算法选择（任务书指定，非本项目自选）

| 用途 | 算法 | 依据 |
|---|---|---|
| 密钥交换 | **X25519（ECDH）** | §45.2 `:1747` |
| 对称加密 | **ChaCha20-Poly1305** | §45.2 `:1748` |
| 密钥派生 | **HKDF** | §45.3 `:1780`（Step 4「通过 HKDF 派生会话密钥」） |
| 消息完整性 | **HMAC** | §45.2 `:1756` |

> **架构约束**：以上算法由任务书指定。**AI-C1 不得自行替换**；如需更换须走 §49 裁决并更新本文件。
> 对应约束：`C-001`。

### 2.2 加密边界

- **强制**：**所有游戏数据必须经 E2EE 通道传输；任何明文路径视为缺陷**（既有契约
  `c2_to_b_security_constraints.md` `C-001`）。
- 适用范围：AI-B1（传输层）、AI-B4（中继）。
- **可验证性判定**：审计方可对任意消息路径做"是否经过 E2EE 封装"的静态检查 +
  抓包检查是否存在明文游戏字段。

### 2.3 前向保密与密钥轮换

- **前向保密**：**每次会话使用独立密钥**（§45.2 `:1749`）。
- **密钥轮换**：**定期更换会话密钥**（§45.2 `:1750`）；§45.3 Step 7 同样要求
  「定期轮换会话密钥（前向保密）」（`:1783`）。
- **私钥存储红线**：私钥**只存内存、不落盘、不进日志**（`.github/ISSUE_TEMPLATE/security-audit.yml`
  第 58 行自检项；§34 `:1051`「不得记录任何隐私数据」）。
- 对应约束：`C-015`（会话密钥轮换与私钥不落盘）。
- **待确认**：轮换周期未在任务书给出具体秒数 → 见 §8。

## 3. 身份验证

| 项 | 决定 | 依据 |
|---|---|---|
| 身份基础 | **无中心化身份，基于密钥对** | §45.2 `:1752` |
| 首次连接 | **交换公钥** | §45.2 `:1753` |
| 公钥指纹验证 | **（可选）防 MITM** | §45.2 `:1754`、§45.3 `:1781` |
| 持久标识 | **禁止生成或使用**任何持久化节点 ID / 设备指纹 / 硬件标识 | `C-003`；§45.2 `:1765` |

> ⚠️ **待裁决-1（重要）**：「公钥指纹验证」在两处均标**（可选）**，但 §53（`:2199`）给
> AI-C4 的是**否决级**验收项「MITM 攻击防御验证」。**AI-C2 不擅自裁决**，详见
> [threat_model.md §6 待裁决-1](threat_model.md) 与 `C-014`。
>
> 在裁决前：**不得**把指纹验证作为强制约束交付 AI-B1/B2；但**必须**在设计中为其预留
> 接口位（避免裁决后返工）。

### 3.1 会话成员关系的表达方式

- 成员关系由**会话内临时密钥对**表达，**不**依赖任何持久账号（`C-003`）。
- **禁止**：以 IP、平台账号 ID、硬件指纹作为身份或成员判据（`C-004`、§45.2 `:1764`）。

## 4. 数据完整性

| 机制 | 要求 | 依据 |
|---|---|---|
| HMAC | **每条消息附带** | §45.2 `:1756` |
| 序列号防重放 | **单调递增**且被校验 | §45.2 `:1757`、`C-010` |
| 时间戳防重放 | 必须有，且设**接收窗口** | §45.2 `:1758`、`C-010` |
| 失败不静默 | 任何校验失败必须**记录 `[SECURITY]` 日志并拒绝该消息** | `C-007`；§34 `:1050` 定义 `[SECURITY]` 前缀 |

- **校验顺序建议（非任务书强制，标 `Probable`）**：先版本 → 再时间戳窗口 → 再序列号 →
  再 HMAC。理由：先做廉价且无状态检查，可降低 DoS 成本。**此顺序为实现建议，不作强制约束。**
- **待确认**：时间戳窗口宽度，以及与 §29.4 的 500ms 延迟要求的兼容性
  （`c2_to_b_security_constraints.md` `:116`）→ 见 §8。

## 5. 中继安全（零信任）

任务书 §45.4（`:1786-1802`）给出中继的**能看 / 不能看 / 不能做 / 必须做**四组要求。

| 类别 | 要求 | 约束 |
|---|---|---|
| **能看到** | 加密后的数据包；**临时**源 / 目标节点标识（非持久） | `C-011` |
| **不能看到** | 游戏数据内容 / 玩家真实 IP / 玩家身份 / **任何元数据** | `C-004`、`C-011` |
| **不能做** | 解密 / 篡改（HMAC 会失败）/ 重放（序列号会失败）/ 追踪玩家 | `C-002`、`C-010` |
| **必须做** | 仅转发加密数据 / **不存储任何数据** / **不记录任何日志** / **可随时退出** | `C-002`、`C-008` |

**架构推论（可验证）**：

1. 中继进程**不得**持有任何会话密钥 → 可用"中继无法解密"的黑盒测试验证。
2. 中继**不得**写入任何持久化存储 → 可用文件系统/进程级观测验证。
3. 中继**不得**产出应用日志 → 注意与"运行平台自身日志"区分；
   **审计要求**：核查中继代码中**不存在**业务日志调用（§34 的 `[RELAY]` 前缀
   **仅用于客户端侧**记录中继交互，**不得**在中继节点本地落盘）。
4. 时间戳/序列号校验失败时，**中继不得**代为容忍或重写。

> ⚠️ **待裁决-3**：「中继无法重放数据」在 §35.15（`:1098`）是测试项，但**不在**
> §40 安全 checklist（`:1309-1319`）。见 [threat_model.md §6 待裁决-3](threat_model.md)。
>
> ⚠️ **取证限制**：因为"不记录日志"本身是约束，**中继侧的证据只能来自审计方自建受控中继**
> （观察内存与转发行为）。任务书**未提供**该能力 → 已记入遗留风险。

## 6. 隐私保护（红线，不可协商）

### 6.1 禁止采集 / 存储 / 传输

```text
IP 地址 / 平台账号 ID / 硬件指纹 / Mod 自发生成持久 ID
设备信息 / 系统信息 / 地理位置 / 任何可追踪标识
```

依据：SECURITY.md §2、§45.2 `:1764-1765`、`c2_to_b_security_constraints.md` `C-003`/`C-004`。
对应约束：`C-003`、`C-004`、`C-016`（日志中不得出现隐私数据）。

### 6.2 禁止行为

```text
扫描进程 / 读内存 / 监控系统 / 上传行为数据 / 中心化封禁
```

依据：§2.4 非目标（`:44-59`）、SECURITY.md §2 与 §6。

### 6.3 本地黑名单的唯一例外（边界必须写清）

黑名单是**唯一**允许记录的"身份相关信息"，且**只记游戏内显示名称**：

```json
{ "entries": [ { "display_name": "PlayerName", "note": "手动添加",
                 "created_at": "2026-01-01T00:00:00Z", "expires_at": null } ] }
```

- **禁止**记录 IP / 平台 ID / 硬件指纹 / 设备信息 / 地理位置（SECURITY.md §2）。
- 默认**精确匹配**（区分大小写），**不启用模糊匹配**（SECURITY.md §2、§46.2 `:1895`）。
- **必须向玩家明确告知代价**：同名玩家会被一起屏蔽；改名后无法继续屏蔽（`R-02`）。
- 对应约束：`C-017`（黑名单字段白名单）。

## 7. 抗攻击

| 攻击 | 机制 | 约束 | 依据 |
|---|---|---|---|
| 抗 Sybil | 信誉系统（新节点信誉低）+ 中继数量上限 + 大量新节点触发警报；PoW 与社交验证**（可选）** | `C-006` | §45.5 `:1806-1814` |
| 抗 DDoS | **速率限制 + 中继隐藏**；信令层与中继层均须有速率限制与**包大小上限** | `C-005` | §45.2 `:1768`、`C-005` |
| 抗 MITM | 公钥指纹验证（**可选** → 见待裁决-1） | `C-014` | §45.2 `:1769` |
| 抗重放 | 序列号 + 时间戳 | `C-010` | §45.2 `:1770` |

> ⚠️ **待裁决-2**：抗 Sybil / 抗 DDoS 在 §53 是**否决级验收项**（`:2200-2201`），
> 但 §36（`:1108-1114`）**未给任何量化指标**，且 §45.5 的两个关键机制标注「（可选）」。
> **「必须验收但无判据」** → 无法客观判定。见 [threat_model.md §6 待裁决-2](threat_model.md)。
