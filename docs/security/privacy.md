## 1. 不可协商的红线

> **Mod 不收集、不存储、不上传任何玩家隐私数据。**
> 无服务器，无官方账号，无中心化身份验证。（SECURITY.md §2）

### 1.1 禁止采集 / 存储 / 传输

```text
IP 地址 / 平台账号 ID / 硬件指纹 / Mod 自发生成持久 ID
设备信息 / 系统信息 / 地理位置 / 任何可追踪标识
```

### 1.2 禁止行为

```text
扫描进程 / 读内存 / 监控系统 / 上传行为数据 / 中心化封禁
```

**依据**：SECURITY.md §2；§45.2 `bloodborne.markdown:1864-1866`；
§2.4 非目标 `:44-59`；`c2_to_b_security_constraints.md` `C-003`/`C-004`。

### 1.3 为什么"无持久 ID"是隐私方案的核心

持久标识是**跨会话关联**的唯一技术基础。移除它之后：

- 无法建立玩家行为档案（即使想建立也做不到）
- 无法跨会话追踪（中继侧同样无法，`C-011`）
- 元数据价值大幅下降（"谁与谁联机"无法稳定归因到同一实体）

**因此 `C-003` 不是一条普通约束，而是隐私架构的承重墙**——
审计时应把它当作首要检查项，而非清单中的一项。

## 3. 唯一例外：本地黑名单（边界必须最窄）

黑名单是**唯一**允许记录身份相关信息的机制，因为它的用途（屏蔽骚扰者）
无法在不引用任何身份信息的情况下实现。

### 3.1 字段白名单

```json
{
  "entries": [
    {
      "display_name": "PlayerName",
      "note": "手动添加",
      "created_at": "2026-01-01T00:00:00Z",
      "expires_at": null
    }
  ]
}
```

**允许字段仅四个**：`display_name` / `note` / `created_at` / `expires_at`。

**禁止**记录：IP / 平台 ID / 硬件指纹 / 设备信息 / 地理位置 / 任何自动推断的标识。

**依据**：SECURITY.md §2；§46.2 `:1879-1918`；约束 `C-017`。

### 3.2 匹配规则

- 默认**精确匹配**（**区分大小写**）
- **不启用模糊匹配**（SECURITY.md §2；§46.2 `:1895`）
- 可选功能（忽略大小写 / 去除首尾空格）若实现，须显式由玩家开启且默认关闭

### 3.3 必须向玩家明确告知的代价（不可省略）

这是本项目**主动接受的取舍**（`R-02`），必须在玩家可见处说明：

1. **同名玩家会被一起屏蔽** —— 因为只按显示名称匹配
2. **改名后无法继续屏蔽** —— 因为没有持久的身份追踪

> ⚠️ 这两条**不是缺陷**，是隐私优先的**必然代价**。
> 不得为了"修复"它们而引入 IP / 账号 ID 记录——那会违反不可协商红线。
> AI-C3 审计**不得**因这两条判 `FAIL`；但**必须**核查告知是否落实。

### 3.4 黑名单不得越界使用

| 禁止 | 依据 |
|---|---|
| 用于 PvE 的自动踢人 / 自动拦截 | `C-012`（反作弊仅限 PvP）；§46.0 `:1854` |
| 上传或共享黑名单 | §2.4（无服务器 / 无中心化）；SECURITY.md §6 |
| 自动推断并加入条目 | `C-017`（字段白名单 + 人工添加） |

## 4. 反作弊与隐私的边界（最容易被误做的地方）

**两套逻辑必须分别验证，不可混淆**（§46.0 `bloodborne.markdown:1932-1958`）：

| 类别 | 适用范围 | 与隐私的关系 |
|---|---|---|
| **始终启用的联机基础完整性**（版本握手 / 协议与 Session ID 校验 / 防重放·包大小·速率限制 / 物品记账与唯一性 / 客机状态不写存档 / 存档原子性） | **全部模式** | 不采集隐私数据；仅校验消息与状态 |
| **行为反作弊**（伤害合理性 / 命中距离 / 攻击频率 / 位置与 HP 突变 / 无敌帧滥用 / 消耗品异常 / 非法状态切换 / 黑名单自动拦截） | **仅 PvP / Invasion** | 基于**游戏内状态**判定，仍**不得**采集进程/内存/系统信息 |

**PvE 模式明令禁止**（§46.0 `:1854`、SECURITY.md §5）：
行为反作弊检测、伤害与命中校验、因疑似作弊自动踢人、写反作弊日志、自动黑名单拦截。

> ⚠️ **审计要点**：把"防重放""速率限制"误当成 PvP 专属功能、
> 要求其在 PvE 关闭，会得出与 §46.0 **相矛盾**的结论。详见
> [constraints.md §2 对照表](constraints.md)。

> ⚠️ **反作弊不得成为监控后门**：即使仅 PvP，"扫描进程""读内存"仍属**全局禁止**
> （§2.4、SECURITY.md §2）。PvP 反作弊只允许基于**游戏内可观测状态**。

## 5. 日志与隐私

- 任何日志（含调试日志）**不得**记录 IP / 平台账号 ID / 硬件指纹 / 设备信息 /
  地理位置或任何可追踪标识（`C-016`；§34 `:1051`）。
- **日志样例必须脱敏**（`docs/README.md:54`）。
- 校验失败路径必须记 `[SECURITY]` 日志（`C-007`），**但该日志同样不得含隐私字段** ——
  这两条要求同时成立，不冲突。
- **文档同样受约束**：`docs/` 内不得出现任何玩家隐私数据（`docs/README.md:54`）。
