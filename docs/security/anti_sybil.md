# 抗 Sybil 机制（Anti-Sybil）

**所有者：AI-C2（Security Architect）｜产出：Phase 0｜实现方：AI-B3（信誉层）、AI-B4（中继上限）**
**证据等级：`Confirmed`（机制项逐条回溯任务书；`Probable` 项已单独标注）**

> **唯一需求来源**：`bloodbrone.markdown`（任务书 v3.0）。冲突时以任务书为准。
> 约束编号见 [constraints.md](constraints.md)（本文件实现 `C-006`）。

---

## 1. 威胁与目标

- **威胁**：身份攻击——Sybil / 身份伪造 / 女巫攻击（§45.1 `:1737`）→ 资产 A-04、A-06、A-07。
- **攻击目标**：以大量虚假节点（a）控制足够多的中继以观察/阻断流量；
  （b）放大 DoS/DDoS；（c）污染信誉系统。
- **防御目标**：使"批量获得网络影响力"的成本显著高于收益，
  且**不引入任何持久身份**（与 `C-003` 冲突的机制一律不可用）。

> ⚠️ **设计红线**：抗 Sybil **不得**通过"给节点分配持久 ID 并记录行为档案"实现——
> 那会直接违反 `C-003`（无持久标识）与 `C-004`（无隐私数据出网）。
> 因此信誉必须**限定在会话/短周期范围内**，且**不得**构成可跨会话追踪的标识。

---

## 2. 任务书给定的机制（§45.5 `bloodbrone.markdown:1806-1814`）

```text
AntiSybil
├── 信誉系统：新节点信誉低
├── 工作量证明（可选）：加入网络需要计算成本
├── 时间成本：新节点需要时间积累信誉
├── 社交验证（可选）：由已知节点推荐
├── 中继节点上限：防止单一实体控制大量中继
└── 异常检测：大量新节点同时加入时触发警报
```

---

## 3. 强制项（进入 `constraints.md` `C-006`，可审计）

| 编号 | 要求 | 可验证性 |
|---|---|---|
| S-1 | **新节点默认低信誉** | 可审计：存在初始信誉值，且低于"可信"阈值 |
| S-2 | **中继数量设上限**，防止单一实体控制大量中继 | 可审计：存在上限常量与执行点 |
| S-3 | **大量新节点同时加入触发警报** | 可审计：存在阈值与告警调用 |

> **S-2 的量化值未在任务书给出** → 属待确认（Q-04）。
> 实现方**不得**自行设定后当成既定参数；须先建 Issue 确认。

**附加要求（防隐私回退，AI-C2 强制）**：

| 编号 | 要求 | 理由 |
|---|---|---|
| S-4 | 信誉数据**不得**包含 IP / 平台账号 ID / 硬件指纹 / 地理信息 | `C-004`、`C-016` |
| S-5 | 信誉数据**不得**构成跨会话可追踪的持久标识 | `C-003` |
| S-6 | 信誉**不得**用于 PvE 的自动踢人或黑名单拦截 | `C-012`（反作弊仅限 PvP） |

## 5. 待裁决与待确认（**AI-C2 不擅自裁决**）

### 待裁决-2：验收无判据（**最需要先解决的问题**）

| 出处 | 情况 |
|---|---|
| §53 `bloodbrone.markdown:2200` | AI-C4 验收含硬性 checkbox「Sybil 攻击防御验证」 |
| §36 `:1101-1119` | 性能与网络指标中**没有**任何 Sybil 量化基线（只有 Ping/RTT/丢包/重传/包频率/反作弊/日志/内存） |
| §45.5 `:1809`、`:1811` | 两个关键机制（PoW、社交验证）均标「（可选）」 |

**冲突**：**「必须验收」但无判据**，且两个可提升门槛的机制都是可选的 →
**无法客观判定通过与否**。

- **裁决方**：**AI-C2 + AI-C4**（§49「性能 vs 安全 → AI-C2，安全优先」）。
- **建议议题**（供裁决参考，**非本文件决定**）：
  1. 验收基线以什么量表达？（如"10× 新节点加入后中继被单一实体控制的比例上限"）
  2. PoW 是否启用；若启用，成本参数如何与 §36 的性能预算权衡。
  3. 「警报」是否需要可观测？（若需要，须注意**不得**为可观测性而记录隐私数据，见 §5 红线）
