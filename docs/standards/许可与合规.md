# 许可与合规（GPL-2.0-or-later）

> **决策**：本项目（代码与文档）采用 **GPL-2.0-or-later**。
> **决策人 / 时间**：Human Owner，2026-10（对「按建议的来」的确认）。
> **依据**：`docs/references/prior-art-bbport-runtime.md`（REF-007）—— 目标运行时 bbport 及其 fork 为
> GPL-2.0(-or-later)，本项目必然要 fork / 修改运行时才能获得插件点（`BB_GAME_LIB`）。
> **最后更新**：2026-10

## 1. 为什么是 GPL-2.0-or-later

- 上游 `deadinside28/bloodborne_pc`：GPL-2.0（HEAD `3c57da41`）；
- `Yharnam-Hunters/bbport`：GPL-2.0-or-later（`src/bbgame.h` 等文件头）；
- 我们的模块要通过 `BB_GAME_LIB` 加载进该运行时的进程，且很可能携带 loader 补丁 —— 分发时需要与 GPL 兼容；
- `LICENSE` 使用 GPL-2.0 全文；文件头用 SPDX 标识 `GPL-2.0-or-later`。

## 2. 分发时的义务

1. 提供完整对应源码（含我们对运行时的修改）；
2. 保留版权与许可声明，不添加额外限制；
3. 修改过的运行时文件要显著标注「已修改」；
4. 不把游戏本体文件、存档、解密素材纳入分发（见 §4）。

## 3. 覆盖范围

- **覆盖**：本仓库的代码、脚本、文档；
- **不覆盖**：Bloodborne 游戏文件、PS4 固件 / 密钥、玩家存档（`.sl2` / `.bloodco`）——
  这些从不入库、不分发（`.gitignore` 与 `SECURITY.md` §9）。

## 4. 与上游规则的一致性

上游 `FORK.md` 明确：必须使用自己的 dump；不得提供或指向游戏文件；不得在仓库里放游戏截图 / 录像
（`docs/assets/ALLOWLIST` 是唯一例外）。因此本项目的验收证据只用日志与工具输出
（见 `scripts/m0/r2_probe/TEST-PROTOCOL.md`，随 M0-R2 准备包落库）。

## 5. 文件头写法

- C / C++ / 头文件：`// SPDX-License-Identifier: GPL-2.0-or-later`
- Markdown / 脚本：用 HTML 注释或文件顶部一行说明。
