## 1. 已经落地的部分（AI-00，无需 AI-C3 动手）

`.github/workflows/pr-guard.yml` 的 `security-gate` 现在会**核对证据**：

- 每条证据必须是独立一行：`- 证据：<仓库内相对路径> | sha256=<64 位小写十六进制> | <查了什么>`
- 至少一条，且必须通过核对
- 被检文件必须真实存在
- 被检文件必须**在本 PR 的改动范围内**（防止拿无关的稳定文件凑证据）
- 哈希必须与文件**当前内容**一致（门禁重算 sha256 并比对）

四种情况一律阻断：**无证据行 / 缺 sha256 / 哈希不符 / 文件不在本 PR 改动内**。

实测矩阵：`test_security_gate.py` 23/23（含 3 个专门的证据失败用例）。

## 2. 需要 AI-C3 做的（`docs/audit/README.md`）

在报告模板里，把现在的 `## 3. 双人独立签核` 之前插入一节，
并把该节及之后的小节编号顺延。建议内容：

```markdown
## 3. 可核对证据（必填，缺一即阻断合并）

> 每条证据必须给出被检文件路径与该文件的 sha256，CI 会**重算并比对**。
> 只写结论不算证据。

- 证据：mod/security/crypto.cpp | sha256=<64 位> | 逐行核对 HMAC 覆盖范围，A-001 通过
- 证据：mod/network/session.cpp | sha256=<64 位> | 核对序列号单调性与重放窗口，A-002/A-003 通过

算哈希：

    sha256sum <文件>                      # Linux / Git Bash
    certutil -hashfile <文件> SHA256      # Windows

⚠️ 这条要求**防不住**什么，必须如实写明：
  * 防不住"抄哈希"（看一眼文件、不算内容、直接复制哈希）
  * 防不住两人未独立判断
  它的作用是把**零成本伪造**变成必须接触真实文件，不是证明结论为真。
```

## 3. 顺带要改的两处（同样在 AI-C3 范围内）

1. **报告模板的编号**：现在模板内是 `## 1..7`，插入新节后要顺延为 `## 1..8`。
   注意 README 自身还有一套 `## 1..5`（审计阶段 / 审计结论 / 报告模板 /

   （AI-00 本轮试改时正是踩了这个坑，出现两个 `## 4`。）

   避免后人以为"签了名就算过"。
