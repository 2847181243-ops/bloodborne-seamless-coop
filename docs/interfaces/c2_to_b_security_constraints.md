## 3. 已确定的强制条款

### C-001 端到端加密强制

- 要求：所有游戏数据必须经 E2EE 通道传输；任何明文路径视为缺陷。
- 适用范围：AI-B1 / AI-B4。
- 验证方式：AI-C3 代码审计 + AI-C4 MITM 测试。

### C-002 中继零信任

- 要求：中继节点仅转发加密数据，**不得**解密、篡改、重放、存储或记录日志。
- 适用范围：AI-B4。
- 验证方式：AI-C4 中继攻击测试（窃听 / 篡改 / 丢弃 / 重放）。

### C-003 无持久标识

- 要求：**不得**生成或使用任何持久化节点 ID、设备指纹、硬件标识。
- 适用范围：AI-B1 / B2 / B3 / B4。
- 验证方式：隐私审计（落盘与出网内容检查）。

### C-004 无隐私数据出网

- 要求：出网报文中**不得**包含 IP、平台账号 ID、硬件信息、地理位置。
- 适用范围：全部网络组件。
- 验证方式：抓包审计 + 代码审计。

### C-005 速率限制

- 要求：信令层与中继层必须有速率限制与包大小上限。
- 适用范围：AI-B1 / B2 / B4。
- 验证方式：AI-C4 DDoS 测试。

### C-006 抗 Sybil

- 要求：新节点默认低信誉；中继数量设上限；大量新节点同时加入触发警报。
- 适用范围：AI-B3。
- 验证方式：AI-C4 Sybil 测试。

### C-007 失败不静默

- 要求：任何校验失败（HMAC / 序列号 / 版本 / 指纹）必须记录 `[SECURITY]` 日志并拒绝该消息。
- 适用范围：全部。
- 验证方式：代码审计。

### C-008 版本握手强校验

- 要求：Mod 版本不一致**拒绝连接**；游戏版本不匹配**拒绝加载**。
- 适用范围：AI-A0 / AI-A2 / 全部网络组件。
- 验证方式：测试矩阵 35.13。
