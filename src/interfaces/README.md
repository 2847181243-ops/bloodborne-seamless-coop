# 接口层（v1，已冻结）

**模块间只能通过这些接口通信**（任务书 §3.6 原则 3）。

## 冻结状态

**v1 已冻结。** 冻结后的任何变更按任务书 **§52-c** 的流程走：

1. 先建 Issue，说明要改哪个接口、为什么现有接口不够、影响哪些模块；
2. 评估影响面（列出所有实现方与调用方）；
3. 提供过渡方案（新增 v2 并让 v1 保留一个版本周期，或给出一次性迁移方案）；
4. 由 AI-00 裁决；
5. 变更落地后同步更新 `docs/interfaces/`。

**禁止**：为了让某个模块方便而直接修改冻结接口，让其他模块"顺手跟着改"。

## 文件

| 文件 | 内容 |
|---|---|
| `version.h` | 接口版本常量 |
| `errors.h` | 错误码 |
| `module_context.h` | Kernel 提供给模块的东西（日志、配置、服务查找） |
| `imodule.h` | 每个模块必须实现的接口 |
| `itransport.h` | 传输能力 |
| `isession.h` | 会话能力 |
| `igameplay.h` | 游戏系统能力 |

## 两条边界规则

1. **不抛异常。** 跨模块边界的函数全部 `noexcept`。
   任务书 §3.6 原则 5 要求「任一非核心模块崩溃，进程存活」——
   异常穿过边界会让一个模块的失败变成整个进程的失败。

2. **不做降级到明文。** `mod.crypto` 失败时拒绝联机（原则 6）。
   接口层不提供任何"先连上再说"的路径。

## 编译独立性（T-004 验收）

每个头文件都可以单独编译，**不依赖 `modules/` 或 `kernel/` 下的任何头文件**。
验证方式见 `tests/contract/`。
